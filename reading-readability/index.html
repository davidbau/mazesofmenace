Reading Readability

By David Bau · October 30, 2026

The aim of the Teleport contest is not just a correct port, but a readable port. But what does it mean for code to be readable? As we get ready for the last month, I'd like to examine some readability measures of the contestants.

Readability has been a classic focus of software engineers for years, and people have proposed a number of automatic ways to measure it: lines of code per function, cyclomatic complexity, the length of identifier names, the ratio of comments to code, even cross-entropy with respect to a language model. But do any of these approaches really capture the notion that we are after? Let's take a look at these measures across the current contestants. As you can see, none of these columns lines up with the last one, except in picking out serteal, whose functions average 165 lines with a complexity of 28. Elsewhere they seem to miss the mark. The original C, which has very readable code, has longer functions than all but serteal and NoahBPeterson, and more branching than all but serteal. Identifier length shows no pattern at all: serteal's identifiers are on average longer than C's while being much less readable. The comment share ranges from 7% to 30% among codebases that are similarly readable. And the language model finds serteal's code the most predictable of all, at 0.44 bits per character against 0.71 to 0.87 for everyone else, despite the fact (or maybe because of the fact) it is largely made of long runs of repetitive numerical manipulations. Predictable is not the same as readable.

One function, three ways

Let's look at a specific example. Here is how one function is implemented in the original C, in richie3366's port, and in serteal's. The function is onscary, which decides whether a monster is frightened by a square: a scroll of scare monster, an engraved Elbereth, or an altar for vampires. First, the C:

boolean
onscary(coordxy x, coordxy y, struct monst *mtmp)
{
    struct engr *ep;
    boolean auditory_scare = (x == 0 && y == 0),
            magical_scare = !auditory_scare;

    if (mtmp->iswiz || is_lminion(mtmp) || mtmp->data == &mons[PM_ANGEL]
        || is_rider(mtmp->data))
        return FALSE;

    if (magical_scare
        && (mtmp->data->mlet == S_HUMAN || unique_corpstat(mtmp->data)))
        return FALSE;

    if ((mtmp->isshk && inhishop(mtmp))
        || (mtmp->ispriest && inhistemple(mtmp)))
        return FALSE;

    if (auditory_scare)
        return TRUE;

    if (IS_ALTAR(levl[x][y].typ)
        && (mtmp->data->mlet == S_VAMPIRE || is_vampshifter(mtmp)))
        return TRUE;

    if (sobj_at(SCR_SCARE_MONSTER, x, y))
        return TRUE;

    return ((ep = sengr_at("Elbereth", x, y, TRUE)) != 0
            && (u_at(x, y)
                || (Displaced && mtmp->mux == x && mtmp->muy == y)
                || (ep->guardobjects && vobj_at(x, y)))
            && !(mtmp->isshk || mtmp->isgd || !mtmp->mcansee
                 || mtmp->mpeaceful
                 || mtmp->data == &mons[PM_MINOTAUR]
                 || Inhell || In_endgame(&u.uz)));
}

The three have almost the same cyclomatic complexity, because they have the same logic: a faithful port has the branches of the C however it is written, and the compiler kept nearly all of them.

The line count is high for serteal, but that is not why it is hard to read. The real problem with serteal is that all the names are gone. In the C and in richie3366's port you can understand code like sengr_at("Elbereth", ...) and sobj_at(SCR_SCARE_MONSTER, ...). But in serteal's code there are comparisons like == 326, which is the scare-monster scroll's object number, and, further down, == 2865336, which is the address of the minotaur's entry in the table of monsters. Here it is using short local variable names like $6, but this doesn't catch the problem systematically: across the whole port serteal's identifiers average 7.6 characters, longer than C's 5.9.

None of these classic measures capture the readability problem. What we really care about is not whether names are short or long, but whether the code is meaningful. We care that someone can actually read the code.

A functional test

So for a better measure of readability, I am using a functional test, with an LLM agent as the reader. Here is how it works.

First, I gathered 500 hard questions about NetHack 5.0, the kind that are hard to guess without looking at the code. I picked them out of a pool of about five thousand questions spread over hundreds of topics: what a scroll of scare monster does to a Cyclops, how far a hero falls when digging down, how many moves on horseback a Knight needs before advancing in riding. Every question is either five-way multiple choice or a number. You can see ten examples at the bottom of this post.

I filtered the questions down by throwing away all the easy ones. In particular, LLMs know a lot about NetHack without reading any code, so I threw out every question that Claude Haiku could answer by guessing, without looking at any code at all (more than one right in four blind tries).

To measure the readability of a codebase, I then ask Haiku to answer the 500 hard NetHack questions using no other resource other than the code. It can list, search and read files, but it cannot run anything. Importantly, it has no access to the internet. It gets half a penny of inference budget per question. I give it a couple of cracks at each question and score the fraction it gets right.

If the code is easy to navigate, with names that say what they do and logic that sits where you would look for it, a small model with a small budget is usually able to quickly answer most questions. But if the code is a maze, Haiku runs out of time before it can figure it out.

I score every codebase twice: once with the comments stripped out of the source, and once with them left in. The first number is about the code itself. The second is about the code as it is written, comments and all. The results table below is based on a snapshot of each contestant's code from the judge's scoring run that started at 00:17 UTC on October 30 (jon-bell squashed their history, so I read their current code). The last column is each contestant's screen parity from the leaderboard at that run: the percentage of screens that match the original game.

Related work

The gold standard for code readability is human evaluation: give code to some programmers, ask them questions, and count the right answers. Scalabrino and colleagues did this, and found that the kinds of metrics in the table above predict it poorly; a reanalysis found some signal when the metrics are combined. Our automated LLM-as-judge procedure uses the same idea with Haiku in the human's seat. For a few dollars, an LLM agent lets us run a simulated readability test with thousands of trials over hundreds of thousands of lines of code, a scale orders of magnitude beyond what is practical with humans.

A few other recent papers use models for readability. CoReEval asks language models to rate the readability of snippets and compares their ratings with people's. But unlike that approach, instead of asking the model to judge the code directly, I am asking the agent to perform a question-answering task. Studies of poor-readability code and of identifier names show that models do worse when code is harder to read, so agent performance seems like a good stand-in for readability.

One of the reasons this test is interesting and new is that it is about readability of a large-scale codebase, not just little snippets. There are several repository-level question-answering benchmarks such as SWE-QA that rate agents based on their ability to answer questions about whole codebases, but here we are doing the reverse. We flip that idea on its head by holding the reader fixed so we can vary and measure the codebase.

In the table above, we have measured the readability of the code itself, with the comments removed, and also of the full source, comments included. For most of the ports, comments are an aid to readability, raising the score by a couple of points (and by about five or six for lockwo and NoahBPeterson). But interestingly, richie3366 comes out slightly less readable when the comments are included. I am not sure why! The drop is tiny, well inside the noise of the measurement.

In at least one case, I can guess why comments might make it harder for Haiku to answer. Take question 1 at the bottom of this post, about digging down. Haiku has an easier time with richie3366's code without comments than with them (3 of 4 tries right without comments, 1 of 4 with). The reason seems to be that when the code has comments and is longer, Haiku reads the comments and spends less of its budget reading actual code lines, consuming valuable moments that, on richie3366's codebase, are better spent reading the code itself. In both cases, Haiku finds and reads the right functions, but without comments, Haiku reads more of the code and notices some details in the logic that override some of the calculations that are seen early in the code. The extra verbosity of the commented code seems to make it a little harder for Haiku to follow in this case.

There is some randomness in these measurements, so gaps smaller than about four points should be treated as possible noise.

Perhaps not surprisingly, a classic transpiled solution like serteal makes it hard to answer questions about the code, since the code is dominated by lookup tables and mostly unreadable functions. When Haiku is trying to figure out how the game works, it needs to confront tables of numbers in serteal's code, and it gets little insight from them. At 18% it is little better than guessing.

The transpilation approach used by NoahBPeterson keeps readable function names and legible structure, so it scores respectably. It does not score as strongly as richie3366 or vtjeng. But its comments do help its readability a lot: with them, it gains about six points.

In principle, it should be possible to write JavaScript that is even more readable than the original hand-written C, with better names, less macro indirection and the logic in one place. But nobody has done that (yet). The C is still the high-water mark, and the best ports sit six or seven points under it.

The questions

I am keeping 500 questions secret, to prevent contestant agents from overfitting to the test. But to give you a concrete sense of what is being tested, here is a sample of ten other representative questions, with answers. After each answer are the scores of each codebase on that specific question, written as two numbers: the percentage of Haiku's tries that came out right with the comments removed (nc) and with the comments left in (c). Haiku made four tries each, so a score moves in steps of 25. For example, "C 50nc/100c" on the first question below means that on the C source Haiku got it right on two of four tries without comments and on all four with them.

1. A non-flying, non-levitating hero digs down with a pick-axe on an ordinary diggable level until they make a hole and fall through. How far do they drop?

  • A. A random number of levels, down to the dungeon's bottom
  • B. Always two levels
  • C. Usually one level, sometimes more, like a trap door
  • D. Exactly one level
  • E. Exactly one level, but only if they have reached the next level before

Answer: D. Scores: C 50nc/100c, richie3366 75nc/25c, vtjeng 100nc/100c, daoa0601 100nc/75c, jon-bell 50nc/75c, rohitgandikota 100nc/75c, lockwo 100nc/100c, NoahBPeterson 75nc/100c, serteal 0nc/25c. (In digactualhole() in dig.c, a hole the hero digs sends them to u.uz.dlevel + 1 through goto_level(). It never consults the hole trap's random destination, so unlike a trap door, which can drop you several levels, digging down always lands you exactly one level below.)

2. Hostile monsters normally refuse to step onto a square holding a scroll of scare monster. Which of these will step onto one anyway?

  • A. The Cyclops (the Healer quest nemesis)
  • B. A hostile dwarf
  • C. A vampire lord
  • D. A minotaur
  • E. A blinded soldier ant

Answer: A. Scores: C 100nc/50c, richie3366 50nc/25c, vtjeng 75nc/50c, daoa0601 75nc/50c, jon-bell 100nc/100c, rohitgandikota 0nc/50c, lockwo 25nc/0c, NoahBPeterson 50nc/50c, serteal 0nc/0c. (In onscary() in monmove.c, a scroll of scare monster or an Elbereth scares only if the monster is not S_HUMAN and not unique (G_UNIQ), and the check for those comes before the scroll check. The Cyclops is unique, so it ignores the scroll. The minotaur and a blinded monster are exempt only from Elbereth, and a vampire lord is not exempt at all.)

3. A hero uses a tinning kit on Medusa's corpse and dies still carrying the tin, and a bones file is saved. What is that tin on the bones level?

  • A. A tin of doppelganger meat
  • B. A tin of human meat
  • C. A tin of Medusa meat, still able to stone whoever eats it
  • D. An empty tin
  • E. A tin of spinach

Answer: D. Scores: C 100nc/100c, richie3366 100nc/100c, vtjeng 0nc/0c, daoa0601 100nc/75c, jon-bell 0nc/0c, rohitgandikota 100nc/100c, lockwo 100nc/75c, NoahBPeterson 75nc/75c, serteal 25nc/25c. (resetobjs() in bones.c cleans up a dead hero's possessions when a bones file is saved. A tin made from a unique monster's meat (unique_corpstat(), which Medusa passes) gets corpsenm = NON_PM, which makes it an empty tin. This keeps a bones level from handing out Medusa-meat tins.)

4. A polymorphed hero walks onto an unseen trap door. In which of these forms do they actually fall through it?

  • A. Ettin
  • B. Storm giant
  • C. Mastodon
  • D. Titan
  • E. Hill giant

Answer: C. Scores: C 100nc/75c, richie3366 0nc/25c, vtjeng 50nc/50c, daoa0601 25nc/75c, jon-bell 25nc/25c, rohitgandikota 100nc/100c, lockwo 25nc/50c, NoahBPeterson 50nc/75c, serteal 0nc/25c. (fall_through() in trap.c says that a hero polymorphed into something of size MZ_HUGE or bigger "doesn't fit through" the trap door. The ettin, hill giant, storm giant and titan are all MZ_HUGE in monsters.h, but the mastodon is only MZ_LARGE, so it is the one that falls.)

5. You play a charged frost horn at a monster that resists fire but not cold, and the blast hits it. Leaving out any extra damage from its items being destroyed, what is the most hit points the blast can take from it?

Answer: 99. Scores: C 100nc/50c, richie3366 75nc/50c, vtjeng 100nc/100c, daoa0601 75nc/100c, jon-bell 75nc/25c, rohitgandikota 50nc/75c, lockwo 50nc/75c, NoahBPeterson 100nc/75c, serteal 25nc/0c. (A frost horn played at a monster fires a cold ray (do_improvisation() in music.c) with rn1(6, 6) dice, so at most 11. In zhitm() in zap.c a cold ray does d(nd, 6) damage, plus d(nd, 3) more if the target resists fire, so the most it can do is 11 × 6 + 11 × 3 = 99.)

6. You melee a floating eye that has been blinded (it cannot see) while you can see it. What happens?

  • A. You are paralyzed only if you lack free action, as usual
  • B. It cannot defend itself, but you lose alignment for attacking a helpless monster
  • C. Its gaze still paralyzes you 2 times in 3
  • D. It cannot defend itself, and you are completely safe with no penalty
  • E. It cannot defend itself; you are safe, but there is a 1 in 500 chance you lose 1 Luck

Answer: E. Scores: C 75nc/100c, richie3366 75nc/100c, vtjeng 50nc/100c, daoa0601 100nc/100c, jon-bell 50nc/50c, rohitgandikota 75nc/75c, lockwo 100nc/100c, NoahBPeterson 50nc/75c, serteal 50nc/50c. (In passive() in uhitm.c, a blinded floating eye cannot paralyze you, because its gaze needs it to see. The code prints "cannot defend itself" and, with probability 1 in 500 (!rn2(500)), also costs you a point of Luck via change_luck(-1). There is no alignment penalty.)

7. Your quest leader has turned hostile toward you. You throw your quest artifact at the leader, who is not paralyzed. What happens?

  • A. The leader catches it, which makes the leader peaceful again
  • B. It flies back to your hand
  • C. The leader catches it and hands or tosses it back, completing the quest
  • D. The leader catches it and keeps it
  • E. It hits the leader like an ordinary missile and falls to the floor

Answer: D. Scores: C 75nc/100c, richie3366 50nc/50c, vtjeng 100nc/0c, daoa0601 100nc/100c, jon-bell 100nc/25c, rohitgandikota 100nc/100c, lockwo 25nc/50c, NoahBPeterson 100nc/100c, serteal 50nc/50c. (In thitmonst() in dothrow.c, a quest leader catches the artifact you throw. A leader who is peaceful hands or tosses it back and calls finish_quest(), completing the quest. A hostile leader instead calls mpickobj() and keeps it, so you lose the artifact and the quest stays open.)

8. Apart from energy regeneration, which extra property increases the amount of Pw you regain on each energy recovery tick?

  • A. Wearing a robe
  • B. Being a Wizard
  • C. Wielding a quarterstaff
  • D. Wearing an amulet of magical breathing
  • E. Regeneration

Answer: D. Scores: C 100nc/100c, richie3366 100nc/100c, vtjeng 100nc/100c, daoa0601 100nc/100c, jon-bell 100nc/100c, rohitgandikota 0nc/0c, lockwo 100nc/100c, NoahBPeterson 75nc/100c, serteal 0nc/0c. (regen_pw() in allmain.c adds rn1(upper, 1) energy on each recovery tick, where upper is (Wis + Int) / 15 + 1, and upper is raised by 2 if you have extrinsic magical breathing, which an amulet of magical breathing gives. Being a Wizard only makes the ticks come more often, not bigger.)

9. A lawful Knight has alignment record 20. He stands on an engraved Elbereth and hits an adjacent hostile jackal in melee. The jackal is currently fleeing because the engraving scared it. The jackal survives. What is his alignment record afterwards?

Answer: 14. Scores: C 50nc/0c, richie3366 0nc/25c, vtjeng 0nc/0c, daoa0601 0nc/0c, jon-bell 0nc/0c, rohitgandikota 25nc/25c, lockwo 0nc/25c, NoahBPeterson 0nc/0c, serteal 0nc/0c. (Two things hit his alignment. setmangry() in mon.c takes 5 points when you attack from an Elbereth square (the code comment says you are "requesting peace and then violating your own request"), and check_caitiff() in uhitm.c takes 1 more because a Knight is hitting a fleeing monster. 20 − 5 − 1 = 14.)

10. A Knight starts the game at Basic riding skill and has no riding practice yet. Counting only riding practice, how many squares must the Knight move while mounted before riding skill can be advanced to Skilled?

Answer: 6000. Scores: C 25nc/25c, richie3366 25nc/25c, vtjeng 75nc/100c, daoa0601 0nc/75c, jon-bell 25nc/50c, rohitgandikota 25nc/0c, lockwo 75nc/75c, NoahBPeterson 0nc/0c, serteal 0nc/0c. (skill_init() in weapon.c starts a Basic skill with practice_needed_to_advance(1) = 20 points of practice. Advancing to Skilled needs practice_needed_to_advance(2) = 2 × 2 × 20 = 80, so 60 more. exercise_steed() in steed.c gives one point per 100 moves while mounted, so that takes 6,000 moves.)
